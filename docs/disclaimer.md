## 一、按步骤分级的风险（先看这张表）

| 步骤 | 风险 | 后果 | 可回滚 |
|---|---|---|---|
| 键盘进控制台、登录 root | 🟢 低 | 只读操作，不改任何文件 | — |
| **修改 `/lge/app_rw/wlan/wlan_startup.sh`** | 🔴 **高** | 该脚本所属 unit 带 `FailureAction=reboot-immediate`，**写错就是重启循环** | ✅ 但需要能进控制台 |
| 放置 `/data/lge/wlan/{hook.sh,serve.sh}` | 🟢 低 | 只是新增文件，不生效 | ✅ 删文件 |
| **`systemctl mask --runtime sshd.socket`** | 🟡 中 | 本次开机内**移除厂商自带 SSH**；若我们的 sshd 起不来，只剩 4445 兜底 | ✅ 重启即恢复 |
| **改 `iptables`** | 🟡 中 | 写错规则可能**把自己锁在外面** | ✅ 重启即恢复 |
| `reboot` 验证持久化 | 🟡 中 | 这是**唯一会暴露 hook 错误**的时刻 | ✅ 物理控制台 |
| ADB 中继（放行 + socat） | 🟢 低 | 运行时规则，重启消失 | ✅ 见回滚命令 |

**只有一处是"写坏就可能起不来"的：`wlan_startup.sh`。** 其余都是运行时改动，重启即复原。

> 对照参考：[iDrive7/8 SSH root](https://github.com/cauliflowermossgrape/idrive7-8-ssh-root)
> 也是同样的写法——"只有 flash 类命令有风险，enable/persist/status 不重写单元"。

## 二、开工前必做（四条，别跳）

1. **备份你要改的文件**
   ```sh
   cp -a /lge/app_rw/wlan/wlan_startup.sh /data/lge/wlan_startup.sh.bak
   ```
2. **保存当前防火墙**
   ```sh
   iptables-save > /data/lge/iptables.before
   ```
3. **确认键盘/控制台可用**（这是唯一不依赖网络的恢复通道）
   —— 先用 USB 键盘验证能 `Alt+F3` 进 root，再做任何事。
4. **确认 4445 兜底通道在工作**，再动 `sshd.socket`。

**做不到第 3 条就不要开始。** 网络通道一旦断掉，物理控制台是唯一出路。

## 三、反脚枪提示（这几件事别做）

- **不要在没验证新 SSH 之前删掉旧入口**——先并存，验证通过再收窄。
- **不要用 `systemctl mask`（永久）**，只用 `--runtime`。永久 mask 会写进不可写的 `/`，
  在 dm-verity 上还可能直接失败。
- **不要因为"看起来不对"就重刷/重装**——本项目不涉及刷写，重启一次比重复操作安全。
- **不要在行驶中操作**。所有步骤在静止或台架上完成。
- **不要把 4445 开放给整个网段**（默认已限制），也不要把它留在公网可达的网络里。

## 五、面向整车厂与供应商

### 项目性质

本项目源自一次**配置检查**：作者在**本人拥有**的车辆上发现登录控制台对 root 空密码放行。
整个过程只使用设备自带的接口完成，厂商二进制未做任何改动。公开目的是：

- 记录真实存在的配置缺陷，便于厂商评估与修复；
- 为其他车主/研究者提供可验证的技术事实；
- 推动供应链关注车机出厂默认配置的安全基线。

**本项目不含**：固件镜像、厂商二进制、提取的接口类、车辆数据、凭据、序列号。

### 缺陷与最小修复建议

| 缺陷 | 建议修复 |
|---|---|
| `/etc/shadow` 中 root 密码为空 | 设置强密码，或锁定账户（`!`） |
| `login` / `busybox.suid su` 接受空密码 | 在认证层禁止空密码 |
| 升级口可接 USB 键盘并触达 getty | 限制控制台切换，或非调试镜像禁用 getty |
| 厂商 unit 使用 `FailureAction=reboot-immediate` | 评估失败策略，避免单点失败导致整车重启循环 |
| 隔离链依赖运行时插入规则 | 考虑对诊断口做更严格的默认策略 |
